Skill（技能）

概念学习资料 · 由 concept-learning-material-generator Skill 生成并经人工核查

一、一句话定义

Skill（技能）是把一组可复用的指令、脚本和资源打包成的一个文件夹（核心是 SKILL.md），让 Agent 在需要时按需加载，从而在特定任务上表现更好。

二、个人解释

如果说 Agent 是"能干活的人"，那 Skill 就是"培训手册 / 工具箱"。它把"怎么做某类任务"的程序性知识沉淀下来，Agent 平时不看，只有遇到相关任务时才按需读取。

Skill 的核心设计是渐进式披露（Progressive Disclosure）：

  • 启动时，只把每个 Skill 的 name + description 预加载进上下文（占用极小）；
  • 任务匹配时，才读取完整 SKILL.md；
  • 需要时，再读取附带脚本 / 参考资料。

这样既能让 Agent"什么都会一点"，又不会把大量无关内容塞满上下文。

三、核心机制或组成

  • 目录结构：必需的 SKILL.md + 可选的 scripts/、references/、assets/。
  • YAML 元数据：顶部写明 name 与 description，供启动时预加载。
  • 渐进式披露：三层按需加载（元数据 → SKILL.md 正文 → 附带文件）。
  • 可执行脚本：让确定性操作（排序、解析 PDF 等）用代码而非 token 生成完成，更可靠、更省。

一个最简 Skill 长这样：

my-skill/
└── SKILL.md   # 唯一必需文件
---
name: my-skill
description: 说明这个技能做什么、何时使用。
---
# 正文：Agent 在任务匹配时读取的详细指令

四、一个具体应用场景

本仓库就是一个实例：concept-learning-material-generator 这个 Skill，把"学习一个新概念"的完整流程（定义 → 解释 → 机制 → 场景 → 辨析 → 自测 → 来源）沉淀进 SKILL.md。

之后无论想学 Agent、RAG、注意力机制还是任何新概念，都能复用同一套流程，只换"概念名称"，就能稳定产出结构一致的学习资料。

五、易混淆点 / 使用边界

  • Skill ≠ 工具 / MCP：Skill 是"程序性知识 + 资源"的打包；MCP 是连接外部工具/数据的协议，二者互补而非替代。
  • Skill ≠ 一次性提示词：提示词用一次就丢；Skill 是可复用、可版本化、可分享的资产。
  • 安全边界：Skill 可包含可执行代码，务必使用可信来源，不要运行来路不明的 Skill。
