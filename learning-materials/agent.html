Agent（智能体）

一、一句话定义

Agent（智能体）是一个能够自主规划、调用工具、与环境交互并持续迭代，从而完成复杂任务的大模型应用系统。

二、个人解释

如果大模型的一次调用是"回答问题"，那么 Agent 就是"派一个人去把事情办成"。

普通的大模型对话是"一问一答、说完就结束"；而 Agent 把大模型当作"大脑"，再给它配上"手"（工具）、"记事本"（记忆）和"眼睛"（环境反馈），让它在一个"思考 → 行动 → 观察结果 → 再思考"的循环里持续推进任务，直到把一件事真正办完，而不是一次问答就停下。

一句话：Agent = 大模型 + 工具 + 记忆 + 循环。

三、核心机制或组成

  • 模型（大脑）：负责推理、决策与生成，是 Agent 的核心。
  • 工具调用（手）：调用函数、API、代码执行、检索等，让 Agent 能"动手做事"。
  • 记忆/状态（记事本）：短期记忆（对话历史）与长期记忆（持久化存储），让多步任务不"断片"。
  • 规划与循环（Agent Loop）：以"思考-行动-观察"的方式迭代推进，常见模式如 ReAct。
  • 环境与反馈（眼睛）：观察每次行动的结果，据此决定下一步。

四、一个具体应用场景

客服退款 Agent：用户说"我要退款"——

  1. Agent 先调用"订单查询"工具，拿到订单信息；
  2. 依据退款规则推理，判断是否符合退款条件；
  3. 符合则调用"退款接口"工具执行退款；
  4. 若接口报错，读取错误信息，选择重试或转人工（环境反馈 + 规划）。

整个过程不是一次问答，而是多轮"思考-行动-观察"的自主推进。

五、易混淆点 / 使用边界

  • Agent ≠ 工作流（Workflow）：Anthropic 明确区分——工作流是用预定义代码路径编排 LLM 与工具，Agent 则由模型动态决定自己的过程。
  • Agent ≠ 单次 LLM 调用：单次调用"一次生成即结束"，Agent 强调多步、循环与自主决策。
  • 不是所有任务都需要 Agent：简单任务用单次调用即可；Agent 会带来额外延迟与成本，应"从最简单方案开始，必要时再升级"。
  • 自主性越高，越需要护栏：越自主的 Agent 越需要 guardrails、权限控制与人工确认。
